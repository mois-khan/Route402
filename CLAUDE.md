# Route402 — Agent Instructions

x402-native payment router for AI agents on Algorand. An agent sends one request; Route402 scores every capable provider on price/latency/reliability, picks one, settles the payment on-chain, and returns the result. The agent never chooses a provider.

**Built for:** NexVerse Hackathon (Algorand Blockchain Club, Aurora University) — Track 2, Composite Entry. Solo build, 2 days.

## Hard rules

1. **Build in phase order.** Never build ahead of the current phase in the implementation plan. A phase starts only when the previous one runs end to end.
2. **Nothing in PRD §16 (Out of scope) gets built.** No auth, no accounts, no Docker, no CI, no multi-chain, no mobile layouts, no rate limiting. Building it costs the demo.
3. **`[VERIFY]` means verify.** The Algorand x402 tooling is fast-moving. Never assume a package name, a spec field, an endpoint, or an ASA ID. Check live docs, then record the finding and the date in `docs/VERIFY.md`.
4. **Never commit secrets.** Wallet mnemonics and private keys live in `.env` only. `.env.example` carries the key names with empty values. MainNet keys never enter the repo.
5. **The scorer stays pure.** `router/src/scorer.ts` takes candidates and constraints, returns scored candidates. No I/O, no DB, no network, no clock. It must be independently testable and explainable on stage.
6. **Rejected candidates are never dropped.** Ineligible providers stay in `candidates[]` with `eligible: false` and a populated `ineligibleReason`, and they must reach the dashboard. Showing the rejects is what makes the decision legible.
7. **No payment without verified delivery.** The guard checks status, parse, non-empty expected field, and timeout before a payment counts. Failure → `status: 'refused'`, provider not paid, request re-routed.
8. **No human in the loop.** The only human-triggered endpoint is `POST /v1/providers/:id/chaos`, and it simulates an external event, not a routing decision. If a demo step needs a human click that a real agent wouldn't make, it is a bug.

## Tech stack — decided, do not substitute

TypeScript (Node 20+) · Fastify (router) · Express (providers) · `algosdk` · `better-sqlite3` · React + Vite + Tailwind (dashboard) · `ws` · Recharts · `concurrently`

All money is **micro-USDC integers**. Never floats, never a bare `price` field. Field names carry the unit: `advertisedPriceMicroUSDC`, `maxPriceMicroUSDC`, `amountMicroUSDC`.

Networks: TestNet for development, MainNet for the final endpoint only.

## Conventions

- Shared types live once, in `shared/src/types.ts`, transcribed from PRD §8. Never redeclare them per workspace.
- Timestamps are epoch milliseconds, always `number`.
- IDs are prefixed: `prov_`, `req_`, `dec_`, `pay_`, `call_`.
- The ledger is append-only. Records are inserted, not mutated, except for defined status transitions on payments.
- One reason string per decision, generated by `explainDecision()`. Never hand-write reason text at a call site.

## Progress tracking

When a phase's exit criteria are met:

1. Tick its checkboxes in [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md).
2. Update the `PROJECT_STATE` object at the top of [docs/index.html](docs/index.html) — phase status, `nextUp`, and the changelog entry.

Both, in the same commit as the work. The HTML page is what gets shown to anyone asking "where is this project?" — a stale page is worse than no page.

## Working style

- Tests are written for the scorer. Nothing else. (PRD §16.)
- Prefer boring and legible over clever. A judge may ask to read the routing code on stage.
- When a decision trades demo quality against engineering quality, demo quality wins — this is a 2-day hackathon build, not a product.
- If something in the PRD looks wrong or unbuildable in the time available, flag it rather than quietly working around it.
