Route402.

An x402-native routing and settlement layer that sits between an AI agent and a pool of paid services — and decides, per request, who gets the job and who gets paid.

AI agents can now pay for services on their own.
Nobody's telling them which one to pick. Route402 does.

01 — Why

The switching cost disappeared. Nothing replaced the decision.

Three things happened in sequence. The third one is the opening.

01

Agents can't buy things

Consuming a paid API means a human creates an account, provisions a key, attaches a card, and reconciles an invoice. Workable for one provider. Structurally impossible across twenty. Completely impossible for a provider the agent found thirty seconds ago.

02

x402 removed the account

x402 turns HTTP 402 Payment Required into a real negotiation. Request a resource, get a price, attach a signed payment, retry. No account, no API key, no invoice. Payment becomes a property of the request.

03

So who picks the provider?

With switching cost gone, a problem appears that did not exist before: something has to choose a provider per request, in real time, on live price, latency and reliability. Today that choice is a hardcoded URL a human picked at build time.

A hardwired provider is, at any given moment, probably not the cheapest, probably not the fastest, and occasionally down — and the agent has no mechanism to notice or care. Route402 is the missing decision layer.

02 — What

One endpoint. The agent never learns who served it.

An agent sends a task to Route402. Route402 evaluates every registered provider that can fulfil it, scores them, selects one, settles the x402 payment on Algorand, returns the result, and updates its own model of the pool based on what just happened.

What the agent sends

POST /v1/route
{
  "capability": "text.summarize",
  "payload":    { "text": "…", "maxWords": 60 },
  "constraints": {
    "maxPriceMicroUSDC": 20000,
    "priority": "balanced"
  }
}

What comes back

{
  "result":  { "summary": "…" },
  "routing": {
    "reason": "Beta selected: 40% cheaper than
               Gamma at comparable p95 latency.",
    "candidatesEvaluated": 3
  },
  "payment": {
    "amountMicroUSDC": 12000,
    "finalityMs": 2840,
    "explorerUrl": "https://…/tx/ABC…"
  }
}

The four guarantees

Legible

Every decision records all candidates — including the rejected ones and why they were rejected — plus one plain-English sentence explaining the pick.

Paid on delivery

A guard verifies the provider actually returned something usable before payment counts. It didn't deliver, it doesn't get paid. The refusal is recorded and visible.

Bounded

The agent sets a hard ceiling. If a provider quotes above its advertised price, the router aborts and re-routes — and logs the discrepancy as a fraud signal.

Unattended

Providers fail, circuits trip, traffic reroutes, the pool recovers. No human in the loop at any point — if a person has to intervene, it's a bug.

03 — How

Six components, one synchronous request.

Routing, payment and settlement all complete inside a single HTTP request — which is only possible because Algorand's finality lands in seconds, not blocks.

Request lifecycle

1
Filter
Drop candidates that don't declare the capability, are circuit-open, exceed the price ceiling, or are explicitly excluded. Rejected candidates are kept in the record with a reason — they are not discarded.
2
Score
Normalise price, latency and unreliability across the candidate set, weight by the requested priority, add a recent-failure penalty. Lowest composite wins. Pure arithmetic — no model, no I/O.
3
Explain
Generate one plain sentence from the score deltas: "Beta selected: 40% cheaper than Gamma at comparable p95 latency." Generated, never hand-templated.
4
Handshake
Call the provider unpaid, receive the 402 with its terms, and validate the quote against the agent's ceiling. A quote above the advertised price aborts the call and is recorded as a fraud signal.
5
Settle
Build the USDC ASA transfer, group it with the sponsor's fee transaction, sign, submit, wait for finality, retry the request with the payment attached.
6
Guard
Verify the response: 2xx, parses, expected field present and non-empty, arrived in time. Any failure marks the payment refused, records it against the provider, and re-routes — up to three attempts.
7
Learn
Write the outcome to the ledger, update the provider's rolling latency and success rate, trip or heal the circuit breaker, broadcast to the dashboard. The next request is scored against a pool that just changed.

The scoring function

// normalised 0..1 across the candidate set
normPrice   = (price - minPrice) / (maxPrice - minPrice)
normLatency = (p95   - minP95)   / (maxP95   - minP95)
reliability = successCount / (successCount + failureCount)

compositeScore =
    Wp * normPrice
  + Wl * normLatency
  + Wr * (1 - reliability)
  + min(consecutiveFailures * 0.15, 0.45)

// lowest wins. max == min → that term is 0.

Reliability never drops below 0.25 in any profile. A cheap provider that doesn't deliver is not cheap. New providers get an optimistic prior so they're sampled rather than starved — explore/exploit, handled explicitly.

04 — Why Algorand

Not a chain we picked. A chain the design requires.

Two capabilities do real work here, and neither is generic. Remove them and the product changes shape.

Atomic groups → composite requests

One agent request may need two providers — summarize, then translate. Both payments go into a single atomic transaction group: both providers are paid and both results return, or nothing settles and nothing is charged. On a chain without this primitive, that needs an escrow contract and multi-block coordination.

Fee abstraction → zero-ALGO agents

The payment is signed by the agent's wallet; a second transaction from the router's sponsor wallet covers fees for the whole group. The agent holds USDC and zero ALGO. An agent can transact without ever acquiring the native token — a genuine onboarding unlock, not a workaround.

And the quiet one: finality lands inside the HTTP request. Routing can only be synchronous — decide, pay, fetch, return — because settlement completes in seconds. With probabilistic finality this design doesn't fit in a request at all.

    07 — Scope

    What's in, and what is deliberately not.

    Two days. The out-list is as binding as the in-list — everything on it is time stolen from the demo.

    Done means all of this is true

    • One endpoint returns a result; the agent never learns the provider
    • Three providers with distinct price/latency profiles, live
    • Every decision lists all candidates, rejects included with reasons
    • Every success settles on-chain and the explorer link resolves
    • The price ceiling is never exceeded
    • A provider killed mid-traffic reroutes with no human intervention
    • A failed provider is never paid, and the refusal is visible
    • Fee abstraction: the agent wallet holds zero ALGO
    • Composite request: two providers, one atomic group
    • Savings vs. naive routing, updating live
    • Endpoint live on MainNet
    • The demo runs clean three consecutive times

    Forbidden — building it costs the demo

    • User accounts, login, sessions, JWT
    • Provider onboarding UI
    • Any payment method other than x402 / Algorand
    • Multi-chain support
    • Rate limiting, quotas, API keys for Route402 itself
    • Kubernetes, Docker Compose, CI/CD
    • Test coverage targets — tests for the scorer only
    • Mobile layouts, dark-mode toggles, landing pages
    • Real third-party AI provider integrations

    Simulated providers with realistic profiles are not a shortcut here — they're the correct choice. The claim is about the routing, and routing is provable without paying OpenAI.
